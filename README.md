# Product Photo

Локальний Python-проєкт для пакетної обробки товарних фотографій.

Основне завдання:
- акуратно відокремити товар від фону;
- замінити фон на чистий білий #FFFFFF;
- зберегти реальні кольори, геометрію та пропорції товару;
- не змінювати назву файлу;
- зберігати фінальний результат у JPG;
- за потреби виправляти складні фото вручну через маску;
- порівнювати оригінал та результат поруч.

# Швидкий старт

1. Відкрити PowerShell у папці проєкту:

cd D:\Git\product-photo

2. Активувати віртуальне середовище:

.\.venv\Scripts\Activate.ps1

Після активації на початку рядка має з'явитися:

(.venv)

---

# Основна автоматична обробка

Початкові фотографії покласти у:

input/

Після цього запустити:

python process.py

Готові файли з'являться у:

output/

Після обробки обов'язково перевірити результат візуально.

Особливу увагу звертати на:
- тонкі краї;
- отвори;
- кільця;
- різьбу;
- кріплення;
- дрібні виступи;
- темні деталі на темному фоні;
- світлі деталі на світлому фоні.

Автоматична маска інколи може зрізати частину деталі.

---

# Якщо автоматична маска пошкодила товар

Для складних фотографій використовується ручне виправлення маски.

Типові проблеми:
- край деталі обрізаний;
- зникло кільце;
- втрачено тонкий виступ;
- вирізано частину корпусу.

Не потрібно переробляти всю фотографію.

Виправляється лише проблемна область.

---

# Ручна маска

1. Створити маску:

python make_mask.py

Після цього відредагувати маску вручну.

Головний принцип:

Домальовувати потрібно тільки ту частину товару, яку автоматична маска помилково видалила.

Не потрібно зафарбовувати весь товар заново, якщо проблема лише в одному місці.

Наприклад:
- відсутня боковина — домалювати боковину;
- обрізане кільце — домалювати кільце;
- втрачений невеликий елемент — відновити тільки його.

2. Застосувати виправлену маску:

python apply_mask.py

Результат перевірити візуально.

---

# Фіналізація

Для фінальної підготовки фотографії використовується:

python finalize.py

Фінальний файл повинен:
- залишатися JPG;
- мати початкову назву;
- мати той самий розмір кадру;
- мати білий фон;
- не містити прозорості;
- не змінювати геометрію товару;
- не збільшувати товар відносно кадру.

---

# Візуальне порівняння

Для перевірки великої кількості фото використовується папка:

compare/

Оригінали копіюються у:

compare/original/

Оброблені файли копіюються у:

compare/output/

Назви файлів повинні збігатися.

Наприклад:

compare/original/70101041.JPG
compare/output/70101041.JPG

Після цього:

cd compare
python compare.py

Браузер відкриється автоматично.

На сторінці:
- ліворуч — оригінал;
- праворуч — оброблений файл.

Усі пари показуються одна за одною.

Це зручно для фінального контролю великої партії фотографій.

---

# Робочий процес

1. Покласти JPG у input/
2. Запустити python process.py
3. Перевірити output/
4. Хороші фото залишити без змін
5. Проблемні фото виправити через ручну маску
6. Запустити python make_mask.py
7. Відредагувати маску
8. Запустити python apply_mask.py
9. Запустити python finalize.py
10. Скопіювати оригінали та результати у compare/
11. Запустити python compare.py
12. Провести фінальну візуальну перевірку

---

# Вимоги до результату

Фінальна фотографія повинна відповідати таким правилам:

- фон — чистий білий #FFFFFF;
- фон займає всю площу кадру;
- зберігається початковий формат JPG;
- зберігається початкова назва файлу;
- зберігаються розмір та пропорції кадру;
- товар не масштабується;
- товар не зміщується без необхідності;
- геометрія товару не змінюється;
- не додаються нові деталі;
- не видаляються реальні деталі;
- не змінюються отвори, різьба, кріплення та маркування;
- зберігаються реальні кольори і фактура матеріалу;
- допускається лише помірна корекція освітлення;
- допускається легка природна тінь;
- результат не повинен виглядати як 3D-рендер.

# Git

Робочі фотографії не зберігаються в репозиторії.

Ігноруються:

input/*
output/*
manual-output/*
manual-mask/*
compare/original/*
compare/output/*

У Git залишаються тільки .gitkeep, щоб структура папок не зникала.

Перевірка:

git status

Перед коммітом бажано бачити тільки зміни коду та документації.

---

# Корисні команди

Перевірити стан:

git status

Перевірити, що Git відстежує у папці порівняння:

git ls-files compare/original
git ls-files compare/output

У нормальному стані має бути тільки:

compare/original/.gitkeep
compare/output/.gitkeep

Запустити порівняння:

cd compare
python compare.py

Повернутися в корінь:

cd ..
